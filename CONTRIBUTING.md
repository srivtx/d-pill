# Contributing

d-pill is a design skill with a machine half: prose that judges, data that
travels, an engine that checks. Every contribution has to keep all three
true. This file is the contract for that.

## What belongs here

Four kinds of change:

1. **A rule** — a judgment that became checkable. The bar is high: a rule
   earns its place only if an agent could verify it with a computed style,
   a geometry measurement, or a grep. "Feels readable" is not a rule.
2. **A reference correction** — prose that is wrong, stale, or
   self-contradictory. The reference files argue with each other on
   purpose; they may not disagree about facts.
3. **An engine fix** — the checker lying, crashing, or passing something
   it should refuse. A false clean is the worst bug this repo can have.
4. **A distribution surface** — an install path, a manifest, a doc index
   row. It ships only with its verification.

Everything else — component kits, a docs site, a rule-count arms race —
is named and refused in `ROADMAP.md`. Read the never list before
proposing.

## The laws

- **`references/base.css` is the authority.** `tokens.json` is its export,
  `tokens.dtcg.json` is that export's standard shape. Change the CSS, run
  `python3 scripts/check-tokens.py`, then `python3 scripts/export-dtcg.py`,
  and fix the loser. Never hand-edit an export.
- **The registry and the engine verify each other.** Every rule in
  `references/rules.json` must have an implementation in
  `scripts/critique.py`, a fix worth reading, and a reference file that
  resolves. Run `python3 scripts/critique.py --list-rules` — drift is the
  bug.
- **Versions agree, or nothing ships.** SKILL.md metadata,
  `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`, and the
  engine's `VERSION` are one number, and `CHANGELOG.md` carries a section
  for it. `python3 scripts/check-skill.py` enforces all of it.
- **Docs travel with the change.** A new file lands with its row in
  `SKILL.md`'s routing table, `README.md`, and `llms.txt`. A changed
  contract lands with its changed docs in the same commit.

## Proposing a rule

A rule is five pieces, in one pull request:

1. The registry entry in `references/rules.json`: `id` (`dpill/…`),
   `severity` (`error` fails the gate; `warn` is a judgment call to read),
   `target`, `summary`, `check`, `fix`, and `reference` — a file that
   exists and carries the law behind the rule.
2. The implementation in `scripts/critique.py`, on the `RULE_IDS` list.
3. A line in the fixtures (`scripts/fixtures/bad.css`, `bad.html`) that
   fires it, so `--selftest` proves it.
4. The prose in the `reference` file, written the way the repo writes:
   one rule per line, tables for mappings, refusals as imperative lists.
5. Nothing else. A rule that needs a second rule to explain it is two
   rules or zero rules.

## The local loop

Run everything CI runs, before you push:

```bash
python3 scripts/check-tokens.py            # the export is true
python3 scripts/export-dtcg.py --check     # the DTCG export is true
python3 scripts/critique.py --list-rules   # registry and engine agree
python3 scripts/critique.py --selftest     # every rule fires where it should
python3 scripts/check-skill.py             # spec-legal, versions agree
python3 scripts/critique.py docs/          # the site passes its own gate
python3 scripts/mcp-smoke.py               # the MCP shell speaks
```

If your change touches `docs/base.css` or the soft recipe, also diff them
against their authorities (`references/base.css`, `references/soft.md`).

## Releasing (maintainers)

1. Bump the version in all four places (see the laws) and write the
   `CHANGELOG.md` section in the same commit.
2. Push to `main`, watch the gate go green.
3. `git tag vX.Y.Z && git push origin vX.Y.Z` — the release workflow
   cuts the GitHub release from the changelog section. Move the floating
   `v1` tag to the same commit by hand; it deliberately does not move
   itself.

## Assets and binaries

`docs/og.png` is the social-preview asset, committed as an image and
regenerated by the maintainer offline (it is not CI-checked — the repo's
scripts stay standard-library-only). `assets/mark.svg` is the mark; it
changes only with a brand decision, not a whim.

## Security

The engine runs on the standard library, offline, with no network and no
subprocesses. Keep it that way; report anything else through
`SECURITY.md`.
