# Access

Accessibility is a design constraint, like the grid. The numeric floors and the checklist live in `critique.md`. This file is how to design so those floors are natural instead of patched on at the end.

## Order

The order of the HTML is the order a person reads and the order a keyboard moves. Do not move things with CSS into a different sequence. If the action is visually last in a dialog, it is last in the DOM too, except where `components.md` puts the safe action first so Enter does not destroy.

One `h1`. Headings step by one. A heading is not a way to get big type. Big type without a heading is a class (`.display`). A heading without looking like one is still a heading, because the outline of the page is a promise.

## Names

Every control has a name a person can hear.

- Inputs have a visible label (`components.md`). Placeholder is an example, not the name.
- Icon buttons name the object and the verb: "Delete invoice 1842".
- Images that carry meaning have alt that says what they show, in the product's voice, not "image" and not a filename. Decorative images have empty alt.
- Links say where they go. "Read the issue" is a name. "Here" is not.
- A dialog has a title that is its accessible name.

Do not hide the only name in a tooltip.

## Not color alone

State is a word, a weight, or a mark, plus color. Required is the word Required. Error is a sentence. Current page is weight plus a mark. A red border with no sentence fails people who cannot see the red, and it also fails the quiet design rule that color is a note.

Charts follow `dataviz.md`: labels on the data, not a color legend as the only key.

## Focus and targets

The ring in `base.css` stays. Design the ring so it looks like it belongs: 2px, offset, `--focus` against the ground. Do not remove it because it clashes with a mock, and do not replace it with a glow.

Targets on a coarse pointer meet the floor in `mobile.md`. A small visual × still has 44px of hit area.

## Motion, contrast, zoom

`prefers-reduced-motion` is already honored in `base.css`. Do not add a second animation path that ignores it. The reduced experience is the same information with no travel: the menu is simply open, the toast is simply there.

`prefers-contrast: more` already strengthens muted text and lines. Do not fade text back down for taste after that.

At a 200% zoom the page reflows to one column. It does not grow a horizontal scrollbar for the whole layout. That is the same recompose as the 720px breakpoint. Test it.

## Cognitive load

One idea per section (`narrative.md`). Plain words (`writing.md`). The same kind of action lives in the same place on every screen: primary at the end of the header cluster, destroy in the overflow or at the end of settings.

Do not start a timer the person cannot pause if the content takes reading. Do not flash. Do not autoplay sound.

A long form says how long it is, or it is split into named steps with a way back. Do not wipe answers when someone goes back.

## Live updates

A toast region is polite. A polite region does not interrupt. An error that blocks the work is inline or a banner, not a toast that vanishes. Loading that replaces a whole view announces itself in text if it takes long enough that the person might think the page died ("Loading orders").

Do not move focus to a notification. Leave the person where they were, unless you are taking them to the error they must fix, and then focus moves to that field on submit only (`interaction.md`).
